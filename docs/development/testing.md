# テスト・検証規約

この文書は、テストの追加・更新、コード整形、静的解析、コード生成、検証結果の報告に関する規約を定める。実装時は [`AGENTS.md`](../../AGENTS.md) と、変更に関係する [`docs/development/architecture.md`](architecture.md) を確認する。

## テスト方針

コード変更時は、変更した振る舞いに関連する既存テストを確認する。可能な範囲で関連するテストを追加・更新する。

実装詳細そのものではなく、外部から確認できる振る舞いをテストすることを優先する。テストを通すためだけに本番コードへ不自然な分岐や公開 API を追加しない。

既存テストを理由なく削除したり、失敗するテストを無効化して解決したことにしない。

## Unit test

ビジネスロジック、状態遷移、データ変換など、UI から分離されたロジックは、可能な範囲で unit test を追加する。

## Widget test

Widget の重要な表示条件やユーザー操作については、必要に応じて widget test を追加する。画面の内部実装ではなく、表示や操作など外部から確認できる振る舞いを検証する。

## 整形・解析・テスト実行

コード変更後は、変更対象に対して `dart format` を実行する。可能な範囲で `flutter analyze` と関連テストを実行する。必要なコード生成がある場合は、プロジェクトの生成方法に従ってコード生成も実行する。

## コード生成ファイル

`.g.dart`、`.freezed.dart` などの自動生成ファイルを直接編集しない。生成元を変更し、プロジェクトの生成方法に従って再生成する。

## 検証結果の報告

静的解析、テスト、コード生成等を実行できなかった場合、または失敗した場合は、成功したものとして扱わない。実行できなかったことまたは失敗したこと、その理由、未確認事項を報告する。
