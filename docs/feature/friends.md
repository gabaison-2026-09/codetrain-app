# フレンド

## 仕様

- ボトムナビゲーション右端の `Profile` を `Friend` に変更し、フレンド画面を割り当てる。
- 画面右上の追加ボタンからユーザー検索モーダルを開く。
- 検索モーダルでは公開用ユーザーIDの完全一致で1件だけ検索し、検索結果からフレンド申請を送信する。
- メイン画面に `フレンド`、`申請中`、`受信` の絞り込みを配置する。
- 初期表示はフレンドのみとし、全ユーザーを無条件に一覧表示しない。
- 送信済み申請は申請中として表示し、取り消せる。
- 受信した申請は承認または拒否できる。
- 承認済みフレンドには連続学習日数を表示する。ユーザー検索、送信申請、受信申請には表示しない。
- 既存フレンドは行の `…` メニューから解除できる。誤操作を避けるため、解除前に確認を表示する。
- 同一ユーザーに対する重複申請、自分自身への申請、既にフレンドであるユーザーへの申請はできない。
- 検索結果と各絞り込みには loading、empty、error の状態を用意する。
- 白背景、黒を中心とした文字と線、ホーム画面で使用している紫を操作中のアクセントに限定して使用する。
- グラデーションとカード型UIは使用せず、行と区切り線を基本に構成する。
- 操作に不要な説明文や注釈文は表示しない。
- 絞り込みタブのタップ領域は高さ48pxとし、タップ時のフィードバックがタブ全体に表示されるようにする。

## データ構成

- 表示データはフレンド関係を表すドメインモデルへ変換し、Widget にAPIレスポンスのJSONを直接記述しない。
- `FriendRepository` を、公開用ユーザーIDの完全一致検索、一覧取得、申請送信、申請取消、承認、拒否、解除の境界とする。
- 既存バックエンドにはフレンド関連APIがないため、[`../API_DESIGN.md`](../API_DESIGN.md) にユーザー検索、関係別一覧、申請送信、申請取消、承認、拒否、解除を行う暫定契約を追加している。
- 検索に使う公開用ユーザーIDはサーバーが一意に発行し、自分のプロフィール取得でも確認できるようにする。
- 検索レスポンスには、公開可能なユーザーID、表示名、アイコン、現在の関係状態が必要である。関係別一覧はページング情報を持ち、承認済みフレンドだけに連続学習日数を含める。
- メールアドレス、外部認証IDなど、検索とフレンド表示に不要な情報はレスポンスへ含めない。

## プライバシー確認

- 本機能は表示名、アイコン、公開用ユーザーID、フレンド関係を他ユーザーとの間で保存・共有する。
- 2026-09-03に、メールアドレスと外部認証IDを使用せず、公開用ユーザーID、表示名、アイコン、フレンド関係を扱うモック実装について確認済み。
- 2026-09-03に、連続学習日数を承認済みフレンドだけへ共有することを確認済み。
- 検索可能な公開範囲、ブロック機能の要否、フレンド解除後の保持方針は、バックエンド接続前に確定する。
